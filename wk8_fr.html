21.1 Calculating correlations between all pairs of continuous variables

But what if we aren’t sure which pair of continuous variables we’re interested in? dosage %>%

21.2 Logistic regression

Every model we fitted in workshop 6 had a continuous outcome (y), such as weight lost. But often in biology the outcome we care about is binary:

  • Did a patient respond to treatment or not?
  • Did a tumour recur or not?
  • Did a mouse survive or not?

A straight line is a poor model for a binary outcome, because it can predict probabilities below 0 or above 1. Logistic regression solves this by modelling the log-odds of the outcome as a linear function of the predictors:

\[ \log\left(\frac{p}{1-p}\right) = \hat\beta_0 + \hat\beta_1 x_1 + \hat\beta_2 x_2 + \dots \]

where \(p\) is the probability of the outcome occurring. This keeps the right-hand side of the equation looking just like a linear model, while guaranteeing that the predicted probability \(p\) stays between 0 and 1.

WarningAssumptions of logistic regression
  • Each continuous predictor is linearly related to the log-odds of the outcome (not to the raw probability)
  • Independence of observations
  • No perfect separation: no combination of predictors perfectly predicts the outcome (this makes the model unstable)
  • A reasonably large sample size relative to the number of predictors, and ideally a good number of events in the rarer outcome category

Note that, unlike linear regression, logistic regression does not assume normally distributed or homoscedastic residuals, since the outcome is binary rather than continuous

21.2.1 Create a binary outcome

The mousezempic dosage data doesn’t come with a binary outcome built in, so let’s create one: we’ll define a mouse as a “responder” (1) if it lost more weight than the median mouse in the study, and a “non-responder” (0) otherwise.

We’ll also rescale drug_dose_g (originally measured in tiny fractions of a gram) into a standardised z-score, so that the resulting odds ratio has a sensible interpretation (“per 1 standard deviation increase in dose”) rather than an astronomically large number per 1 g increase.

dosage <- dosage %>%
  na.omit(weight_lost_g, drug_dose_g) %>%
  mutate(
    responder = case_when(
      weight_lost_g > median(weight_lost_g) ~ 1,
      weight_lost_g < median(weight_lost_g) ~ 0,
      .default = NA),
    drug_dose_z = as.numeric(scale(drug_dose_g))
  )

dosage %>% count(responder)

21.2.2 Check for separation

Before fitting the model, we should check for separation, where a predictor perfectly separates responders from non-responders, which would make the model unstable. A quick contingency table is one way to check this by eye:

table(dosage$mouse_strain, dosage$responder)

  BALBc   53  11

  CD1    112  32

Every strain contains a mix of responders and non-responders, so separation isn’t a concern here.

21.2.4 Interpret coefficients as odds ratios

The raw coefficients from summary() are on the log-odds scale, which isn’t very intuitive. We can make them easier to interpret by exponentiating them. ‘Exponentiating’ converts each coefficient into an odds ratio (OR), which is how much the odds of responding multiply for each one-unit increase in that predictor (holding other predictors constant). The easiest way to do this is using the tidy() function from the broom package:

tidy(logit_model, exponentiate = TRUE, conf.int = TRUE)
# A tibble: 4 × 7
  term               estimate std.error statistic     p.value conf.low conf.high
  <chr>                 <dbl>     <dbl>     <dbl>       <dbl>    <dbl>     <dbl>
1 (Intercept)           0.362     0.379     -2.68     7.37e-3    0.165     0.741
2 drug_dose_z          14.7       0.493      5.45     5.08e-8    5.91     41.2  
3 mouse_strainBlack6   27.1       1.15       2.87     4.15e-3    3.94    554.   
4 mouse_strainCD1       4.57      0.500      3.04     2.38e-3    1.80     13.0

Both drug_dose_z and mouse_strain have p values well below 0.05, so we can reject the null hypothesis for each: a one standard deviation increase in dose is associated with roughly a 13-fold increase in the odds of responding (95% CI approximately 5- to 36-fold), holding strain constant. Relative to the BALBc reference strain, Black6 and CD1 mice both have substantially higher odds of responding at the same dose.

21.3 Running many t-tests at once with group_by()

In workshop 6, we learnt to run a single t-test at a time. But sometimes, you’ll want to run the same comparison many times over: for example, comparing treated vs control samples for each of several bacterial species, or the effects of many different drugs vs their matched control compounds.

Imagine an experiment where four bacterial species were grown either with no treatment (untreated) or in the presence of an antibiotic (antibiotic). After 24 hours, bacterial growth was measured as optical density at 600 nm (od600), with five replicate cultures per condition:

growth_data

t.test(od600 ~ treatment, data = growth_data)

What if instead, we want one t-test per species?

We can do with the help of the group_by() function (see Section 10.4) and the t_test() from the rstatix package. rstatix contains a lot of helpful functions for running statistical tests on tidy data, and you can install it using the following code:

install.packages("rstatix")

When you pipe a grouped dataframe into t_test(), a t-test is run separately within each group, and gives us back a tidy tibble with one row per group:

growth_data %>%
  group_by(species) %>%
  t_test(od600 ~ treatment)

The p values are reported in the p column. Conveniently, t_test() automatically applies a mutliple-testing correction to the p values by default (see ?t_test for more information).

21.4 Other topics to explore

NoteWhere to go next
  • Effect sizes: a p value tells you whether an effect exists, but not how big it is. Cohen’s d (for t-tests), eta-squared (for ANOVA) and Cramér’s V (for chi-squared) are standard ways to quantify the size of an effect, independent of sample size the effectsize package is a good place to start.
  • Repeated measures and mixed-effects models: every test in workshop 6 assumes independent observations, but biological data often isn’t (e.g. multiple measurements from the same mouse, or mice from the same litter/cage). Mixed-effects models (via the lme4 or nlme packages) let you account for this kind of clustering directly in the model.
  • Predicted probabilities and marginal effects: for logistic (and other) regression models, it’s often more intuitive to talk about a predicted probability than a raw coefficient or odds ratio. The ggeffects package’s ggpredict() function and the emmeans package are both great tools for this, and for comparing predictions between groups while holding other variables constant.
  • Checking model assumptions visually: rather than checking each assumption one at a time, the performance package’s check_model() function produces a full set of diagnostic plots (residuals, normality, homoscedasticity, multicollinearity and more) for a linear or logistic regression model in a single line of code.
  • Sample size and power: before you even collect your data, it’s helpful to know how many samples you need to reliably detect an effect of a certain size. The base R power.t.test() function and the pwr package can help answer this for many of the tests covered in workshop 6.

If we used the `t.test()` function on this entire dataframe, R would lump all four species together and compare *all* antibiotic cultures to *all* untreated cultures:

```{r}
t.test(od600 ~ treatment, data = growth_data)
```

What if instead, we want one t-test **per species**?

We can do with the help of the `group_by()` function (see @sec-grouping) and the `t_test()` from the `rstatix` package. `rstatix` contains a lot of helpful functions for running statistical tests on tidy data, and you can install it using the following code:

```{r}
#| eval: false
install.packages("rstatix")
library(rstatix)
```

```{r}
#| echo: false
library(rstatix)
```

When you pipe a grouped dataframe into `t_test()`, a t-test is run separately within each group, and gives us back a tidy tibble with one row per group:

```{r}
growth_data %>%
  group_by(species) %>%
  t_test(od600 ~ treatment)
```
The p values are reported in the `p` column. Conveniently, `t_test()` automatically applies a mutliple-testing correction to the p values by default (see `?t_test` for more information).

## Other topics to explore

::: {.callout-note title="Where to go next"}
-   **Effect sizes**: a p value tells you whether an effect exists, but not how big it is. Cohen's d (for t-tests), eta-squared (for ANOVA) and Cramér's V (for chi-squared) are standard ways to quantify the *size* of an effect, independent of sample size the [effectsize](https://easystats.github.io/effectsize/) package is a good place to start.
-   **Repeated measures and mixed-effects models**: every test in workshop 6 assumes independent observations, but biological data often isn't (e.g. multiple measurements from the same mouse, or mice from the same litter/cage). Mixed-effects models (via the [lme4](https://cran.r-project.org/package=lme4) or [nlme](https://cran.r-project.org/package=nlme) packages) let you account for this kind of clustering directly in the model.
-   **Predicted probabilities and marginal effects**: for logistic (and other) regression models, it's often more intuitive to talk about a *predicted probability* than a raw coefficient or odds ratio. The [ggeffects](https://strengejacke.github.io/ggeffects/) package's `ggpredict()` function and the [emmeans](https://rvlenth.github.io/emmeans/) package are both great tools for this, and for comparing predictions between groups while holding other variables constant.
-   **Checking model assumptions visually**: rather than checking each assumption one at a time, the [performance](https://easystats.github.io/performance/) package's `check_model()` function produces a full set of diagnostic plots (residuals, normality, homoscedasticity, multicollinearity and more) for a linear or logistic regression model in a single line of code.
-   **Sample size and power**: before you even collect your data, it's helpful to know how many samples you need to reliably detect an effect of a certain size. The base R `power.t.test()` function and the [pwr](https://cran.r-project.org/package=pwr) package can help answer this for many of the tests covered in workshop 6.
:::
