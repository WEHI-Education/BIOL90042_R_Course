19  Workshop 6: Statistics in R

So far in BIOL90042, we’ve learnt how to identify patterns in our data by examining descriptive/summary statistics (mean, median etc) and visualising it with various plot types. In this workshop, we will learn how to formally test whether these patterns are statistically significant, using R. We will start by talking about how to check the assumptions behind a statistical test, then work through various different types of tests, as well as linear regression. We’ll also see how the ggpubr package can help us visualise many of these tests directly on a plot.

Please note that this is not a statistics subject, so this workshop will skip over most of the mathematics underlying these tests. If you’re interested, a nice overview can be found in the Learning Statistics With R ebook.

  6. Construct simple and multiple linear regression models, including correcting for a confounding variable

19.1 Testing associations between categorical variables

The first type of test we will cover is that of associations between categorical variables. This will allow us to answer questions such as ‘is there a systematic association between mouse strain and sex in our mousezempic study?’

19.1.1 Chi-squared test

The chi-squared (\(\chi^2\)) test of independence compares the observed frequency of every combination of two categorical variables against the frequency we would expect if the two variables were completely unrelated (independent).

In other words it tests the following hypotheses:

  • Null hypothesis (\(H_0\)): the two categorical variables are independent (no association)
  • Alternate hypothesis (\(H_1\)): the two categorical variables are associated

Before perfomring any statistical test, we need to first consider the assumptions of that test and ensure our data conforms to these. The assumptions of the (\(\chi^2\)) test are as follows:

WarningAssumptions of the (\(\chi^2\)) test
  • Observations are independent of one another (each mouse is only counted once, and they do not influence each other)
  • The categories of each variable are mutually exclusive and exhaustive (every mouse falls into exactly one strain and one sex)
  • Expected cell counts are reasonably large — a common rule of thumb is that no more than 20% of cells should have an expected count below 5. When this is violated (e.g. for small or sparse tables), use fisher.test() instead, which computes an exact p value.

You can generally account for these assumptions in your study design.

In order to conduct a (\(\chi^2\)) test, the first thing we need to do is construct a contingency table, that counts up the number of observations for every combination of our two categorical variables. In workshop 3, we discussed how to do this using pivot_wider() (see Section 10.6.1.1), mostly as an exercise to explain how to use that function.

However, there is an easier way, using the base R function table(). Note that, for base R functions, we need to access the column names with $, as we did in workshop 1 (see Section 4.6.3).

# assign it to a variable, we'll need this
# later to do the test
strain_sex_table <- table(dosage$mouse_strain, dosage$sex)

# view the table
strain_sex_table
        
         female male
  BALBc      34   34
  Black6     58   61
  CD1        73   73

As we can see, the counts in every cell are comfortably above 5, so a (\(\chi^2\)) test is appropriate here.

You may also notice that the proportion of male and female mice looks very similar across all three strains, suggesting there may be no association between strain and sex. Let’s still do the (\(\chi^2\)) test though, to learn how it works. We can do this using the chisq.test() function:

chisq.test(strain_sex_table)

    Pearson's Chi-squared test

data:  strain_sex_table
X-squared = 0.048607, df = 2, p-value = 0.976

The test statistic is very small (0.05) and the p value (0.98) is far greater than 0.05, so we fail to reject the null hypothesis.

We can therefore conclude that there is no evidence of an association between mouse strain and sex in our dosage data, which is consistent with sex being allocated at random with respect to strain as we would hope for a well-designed experiment.

19.2 Comparing means: t-test and ANOVA

Another very common statistical task is testing whether a continuous outcome differs between groups. For example, does weight_lost_g differ between male and female mice, or between mouse strains?

WarningAssumptions of the t-test and ANOVA
  • Observations are independent of one another
  • The outcome is approximately normally distributed within each group (rather than in the dataset overall). If not, use a non-parametric test like wilcox.test() or kruskal.test()
  • The groups have approximately equal variance. If not, use Welch’s correction: t.test(var.equal = FALSE) or oneway.test()

19.2.1 Comparing two groups: the t-test

Let’s use a t-test to determine whether weight_lost_g differs between male and female mice.

First, it’s always a good idea to visualise the data:

ggplot(dosage, aes(x = sex, y = weight_lost_g)) +
  geom_boxplot() +
  # set ylim to 0 so as not to magnify small differences
  ylim(0, 6.5)

Looking at the plot, it seems like there might be a slight difference, and the variances appear fairly similar

Let’s now check the normality assumption, using a QQ-plot for each group. A QQ (quantile-quantile) plot compares the quantiles of our data against the quantiles we would expect if the data was perfectly normally distributed. We can make a QQ-plot using ggplot2 with geom_qq(), adding a reference line with geom_qq_line() to make it easier to judge how similar our data is to the normal distribution:

ggplot(dosage, aes(sample = weight_lost_g)) +
  geom_qq() +
  geom_qq_line() +
  # facet because we need to check normality for each group
  facet_wrap(~sex)

If our data were normally distributed, the points would sit neatly along the diagonal reference line.

Both groups show a distinct curve away from the straight reference line, which suggests weight_lost_g is not normally distributed in either group.

We can confirm this with a Shapiro-Wilk test (using shapiro.test()) in each group:

dosage %>%
  filter(sex == "male") %>%
  # shapiro.test() needs a vector, so use pull()
  pull(weight_lost_g) %>%
  shapiro.test()

    Shapiro-Wilk normality test

W = 0.92504, p-value = 1.227e-07
dosage %>%
  filter(sex == "female") %>%
  pull(weight_lost_g) %>%
  shapiro.test()

    Shapiro-Wilk normality test

data:  .
W = 0.91931, p-value = 6.155e-08

Both p values are far below 0.05, so we reject normality in both groups.

This means a t-test isn’t actually valid here (we should use the non-parametric alternative wilcox.test() instead), but for the sake of showing you how one works in R, let’s run it anyway. We can compare this to the non-parametric test in a minute.

To run a t-test in R, use the t.test() function, and provide it three arguments:

  • A formula of the format y ~ x (outcome ~ grouping variable)
  • data, the dataframe that contains columns y and x from the formula
  • var.equal = TRUE for a Student’s t-test (assuming variances are equal) or var.equal = FALSE for Welch’s t-test (assuming variances are not equal)
t.test(
  weight_lost_g ~ sex, # compare weight lost across sex
  data = dosage, # use dosage data
  var.equal = TRUE # student t-test
  )

            3.862273             4.545685

The p value (4.90e-16) is much smaller than 0.05, suggesting (as the output says), that there is a difference in the mean amount of weight lost by female and male mice. This is not unexpected: we know that male mice weigh more to begin with, so they therefore have more weight to lose than female mice.

19.2.2 Comparing more than two groups: ANOVA

The t-test only compares two groups, so while we could use it to compare male vs female mice, if we want to compare weight_lost_g across all three mouse strains at once, we need its multi-group extension: the ANOVA (analysis of variance). Rather than comparing two means directly, ANOVA compares the variance between groups to the variance within groups, to test whether at least one group mean differs from the others.

19.2.3 Non-parametric tests

When a parametric assumption (i.e. normality) is badly violated, we can turn to a non-parametric alternative instead. These tests don’t assume the outcome is normally distributed and instead test for differences in the ranks of the data.

WarningAssumptions of the Wilcoxon and Kruskal-Wallis tests
  • Observations are independent of one another
  • The outcome variable is at least ordinal (i.e. it can be meaningfully ranked)
  • If you want to interpret the result as a difference in medians specifically (rather than just ‘the distributions differ’), the groups should have similarly shaped distributions

Non-parametric tests are more robust to outliers and skewed distributions than their parametric counterparts, but they can be somewhat less powerful to detect a true effect when the data are actually normally distributed. Therefore, you should only use them when you really need to.

19.2.3.1 The Wilcoxon rank-sum test

The Wilcoxon rank-sum test (also called the Mann-Whitney test when applied on two samples, like we will do here) is the non-parametric equivalent of the t-test we covered earlier. Instead of comparing means, it tests whether one group tends to have overall higher or lower ranked values than the other.

Let’s revisit our comparison of weight_lost_g between male and female mice. We can use it by simply replacing t.test() with wilcox.test()

wilcox.test(weight_lost_g ~ sex, data = dosage)

    Wilcoxon rank sum test with continuity correction

data:  weight_lost_g by sex
W = 6874.5, p-value = 1.813e-15
alternative hypothesis: true location shift is not equal to 0

The p value is again far smaller than 0.05, so both tests agree here: male and female mice differ in weight lost.

19.2.3.2 The Kruskal-Wallis test

The just like the t-test, the Wilcoxon test only compares two groups. The non-parametric version of the ANOVA we ran above is called the Kruskal-Wallis test, and we can run it using the kruskal.test() function:

kruskal.test(weight_lost_g ~ mouse_strain, data = dosage)

    Kruskal-Wallis rank sum test

data:  weight_lost_g by mouse_strain
Kruskal-Wallis chi-squared = 212.09, df = 2, p-value < 2.2e-16

19.3 Correlation between continuous variables

So far, we have considered situations where both, or one of our variables were categorical. If both of our variables are continuous, we can measure the strength and direction of a linear relationship between them using a correlation coefficient.

A correlation coefficient ranges from -1 to 1, where:

  • Values close to 1 indicate a strong positive relationship (as one variable increases, so does the other)
  • Values close to -1 indicate a strong negative relationship (as one variable increases, the other decreases)
  • Values close to 0 indicate little to no linear relationship
WarningAssumptions of the Pearson correlation
  • The relationship between the two variables is linear (check with a scatterplot before you calculate r!)
  • Both variables are continuous
  • No extreme outliers, which can heavily distort the correlation coefficient
  • Ideally, both variables are roughly normally distributed

If any of these are violated (e.g. the relationship is non-linear, or there are outliers), use the non-parametric Spearman correlation instead. Spearman correlation only assumes the relationship is monotonic, since it works on the ranks of the data rather than the raw values.

19.4 Visualising statistical tests with ggpubr

So far, we’ve been running our tests and making our plots in two separate steps. The ggpubr package (which extends ggplot2) makes it easy to combine the two, by adding the result of a statistical test directly onto a plot as an annotation. This is a great way to make quick, publication-ready figures without having to manually copy test statistics and p values into a title or label.

19.4.1 Adding a test result to a boxplot

The ggboxplot() function works similarly to ggplot() + geom_boxplot(), but returns a plot we can layer statistical annotations onto with stat_compare_means().

Let’s revisit our comparison of weight_lost_g between male and female mice, this time adding the t-test result directly onto the plot:

ggboxplot(
  data = dosage,
  # unlike in the ggplot() function, x and y are
  # supplied directly, not in aes()
  x = "sex", y = "weight_lost_g",
  # in ggpubr, you add jitter using the 'add' argument
  add = "jitter") +
  stat_compare_means(method = "t.test") +
  labs(x = "Sex", y = "Weight lost (g)")

The same idea works for our three-strain comparison, using method = "kruskal.test" (or method = "anova"):

ggboxplot(dosage, x = "mouse_strain", y = "weight_lost_g", add = "jitter") +
  stat_compare_means(method = "kruskal.test") +
  labs(x = "Mouse strain", y = "Weight lost (g)")

We can get ggpubr to add pairwise comparisons too, by supplying a list of the pairs we’re interested in to the comparisons argument:

ggboxplot(dosage, x = "mouse_strain", y = "weight_lost_g", add = "jitter") +
  # get the pairwise comparisons
  stat_compare_means(
    comparisons = list(c("BALBc", "Black6"), c("BALBc", "CD1"), c("Black6", "CD1"))) +
  # get the overall p value and test name
  stat_compare_means(method = "kruskal.test", label.y = 8) +
  labs(x = "Mouse strain", y = "Weight lost (g)")

Annoyingly, we have to run stat_compare_means() twice, because each call only adds one type of label of the plot (either the pairwise comparisons or the overall p value and test name), but this is the struggle that comes with using functions written by other people, sometimes the interface doesn’t quite make sense!

19.5 Linear modelling (in the tidyverse)

As you may recall from lecture 4, linear models are very useful for testing for significant associations between variables, or significant differences between groups. They have the advantage of being able to correct for the effects of other variables, and thereby remove unwanted sources of variation that could otherwise reduce our ability to discover true relationships.

WarningAssumptions of linear regression
  • Linearity: the relationship between each predictor and the outcome is a straight line
  • Independence: the residuals (the differences between observed and predicted values) are independent of one another
  • Homoscedasticity: the residuals have roughly constant variance across the range of fitted values
  • Normality of residuals: the residuals are approximately normally distributed (this matters most for small samples — with a large enough sample, the model is fairly robust to this)
  • For multiple regression specifically: predictors shouldn’t be too strongly correlated with one another (multicollinearity)

19.5.1 Testing differences between groups (discrete x)

Earlier in this workshop (see Section 19.2.1), we used an independent t-test to check whether weight_lost_g differs between male and female mice. A simple linear regression with a single, two-level categorical predictor is mathematically identical to that t-test.

19.5.5 Correcting for covariates

So far we have tested relationships between a independent (x) and a dependent (y) variable.

Often we want to ensure that other possible sources of variation are minimised so that we can better detect true differences in our ‘main effect of interest’. Say we want to understand whether drug dose affects weight lost regardless of mouse strain. In other words, we want to subtract the mean effect of any strain-specific differences.

We already saw in our ANOVA and Kruskal-Wallis tests earlier that weight_lost_g differs noticeably between strains (Black6 mice lose more weight on average). Therefore, mouse strain is a plausible confounder of the drug dose/weight lost relationship.

To test the dose effect while correcting for strain, we can add mouse_strain to the model:

dosage %>%
  lm_test(weight_lost_g ~ drug_dose_g + mouse_strain)

19.5.6 The role of linear modelling in bioinformatics

Everything we’ve covered today is the basic statistical foundation for the more advanced bioinformatics techniques we’ll learn in upcoming workshops. A differential expression analysis, for example, fits exactly the same kind of linear model we’ve built today, just repeated across thousands of outcomes at once (individual genes, proteins or metabolites), while correcting for confounders like batch effects, and handling data that’s rarely as well-behaved as ours (requiring extra filtering, transformation, and care around mean-variance relationships). Doing this at scale is a computationally demanding task, which is why R packages such as limma and edgeR, bundle the expression data, sample/gene metadata and model design together into a single specialised object, then fit all of the models and generate thousands of results in one command. We’ll learn about this workflow in upcoming workshops.

Linear modelling is also foundational to machine learning, which focuses on trying to use the coefficients from a fitted model, combined with the predict() function, to make predictions about new data. We’ll explore machine learning in more detail in our final workshop.

## Testing associations between categorical variables

The first type of test we will cover is that of associations between categorical variables. This will allow us to answer questions such as 'is there a systematic association between mouse strain and sex in our mousezempic study?'

### Chi-squared test {#sec-chisq}

The chi-squared ($\chi^2$) test of independence compares the observed frequency of every combination of two categorical variables against the frequency we would expect if the two variables were completely unrelated (independent).

In other words it tests the following hypotheses:

-   Null hypothesis ($H_0$): the two categorical variables are independent (no association)
-   Alternate hypothesis ($H_1$): the two categorical variables are associated

Before perfomring *any* statistical test, we need to first consider the assumptions of that test and ensure our data conforms to these. The assumptions of the ($\chi^2$) test are as follows:

::: {.callout-warning title="Assumptions of the ($\chi^2$) test"}
-   Observations are independent of one another (each mouse is only counted once, and they do not influence each other)
-   The categories of each variable are mutually exclusive and exhaustive (every mouse falls into exactly one strain and one sex)
-   Expected cell counts are reasonably large — a common rule of thumb is that no more than 20% of cells should have an expected count below 5. When this is violated (e.g. for small or sparse tables), use `fisher.test()` instead, which computes an exact p value.

You can generally account for these assumptions in your study design.

:::

In order to conduct a ($\chi^2$) test, the first thing we need to do is construct a contingency table, that counts up the number of observations for every combination of our two categorical variables. In workshop 3, we discussed how to do this using `pivot_wider()` (see @sec-pivot-wider), mostly as an exercise to explain how to use that function.

However, there is an easier way, using the base R function `table()`. Note that, for base R functions, we need to access the column names with `$`, as we did in workshop 1 (see @sec-dataframes).


```{r}
# assign it to a variable, we'll need this
# later to do the test
strain_sex_table <- table(dosage$mouse_strain, dosage$sex)

# view the table
strain_sex_table
```
As we can see, the counts in every cell are comfortably **above 5**, so a ($\chi^2$) test is appropriate here.

You may also notice that the proportion of male and female mice looks very similar across all three strains, suggesting there may be no association between strain and sex. Let's still do the ($\chi^2$) test though, to learn how it works. We can do this using the `chisq.test()` function:

```{r}
chisq.test(strain_sex_table)
```
The test statistic is very small (0.05) and the p value (0.98) is far greater than 0.05, so we **fail to reject the null hypothesis**.

We can therefore conclude that there is no evidence of an association between mouse strain and sex in our `dosage` data, which is consistent with sex being allocated at random with respect to strain as we would hope for a well-designed experiment.

## Comparing means: t-test and ANOVA {#sec-compare-means}

Another very common statistical task is testing whether a continuous outcome differs between groups. For example, does `weight_lost_g` differ between male and female mice, or between mouse strains?

::: {.callout-warning title="Assumptions of the t-test and ANOVA"}
-   Observations are independent of one another
-   The outcome is approximately normally distributed **within each group** (rather than in the dataset overall). If not, use a non-parametric test like `wilcox.test()` or `kruskal.test()`
-   The groups have approximately equal variance. If not, use Welch's correction: `t.test(var.equal = FALSE)` or `oneway.test()`
:::

### Comparing two groups: the t-test {#sec-ttest}

Let's use a t-test to determine whether `weight_lost_g` differs between male and female mice.

First, it's always a good idea to visualise the data:

```{r}
ggplot(dosage, aes(x = sex, y = weight_lost_g)) +
  geom_boxplot() +
  # set ylim to 0 so as not to magnify small differences
  ylim(0, 6.5)
```

Looking at the plot, it seems like there might be a slight difference, and the variances appear fairly similar


Let's now check the normality assumption, using a QQ-plot for each group. A **QQ (quantile-quantile) plot** compares the quantiles of our data against the quantiles we would expect if the data was perfectly normally distributed. We can make a QQ-plot using `ggplot2` with `geom_qq()`, adding a reference line with `geom_qq_line()` to make it easier to judge how similar our data is to the normal distribution:

```{r}
ggplot(dosage, aes(sample = weight_lost_g)) +
  geom_qq() +
  geom_qq_line() +
  # facet because we need to check normality for each group
  facet_wrap(~sex)
```

If our data were normally distributed, the points would sit neatly along the diagonal reference line.

Both groups show a distinct curve away from the straight reference line, which suggests `weight_lost_g` is not normally distributed in either group.

We can confirm this with a Shapiro-Wilk test (using `shapiro.test()`) in each group:

```{r}
dosage %>%
  filter(sex == "male") %>%
  # shapiro.test() needs a vector, so use pull()
  pull(weight_lost_g) %>%
  shapiro.test()

dosage %>%
  filter(sex == "female") %>%
  pull(weight_lost_g) %>%
  shapiro.test()
```

Both p values are far below 0.05, so we reject normality in both groups.

This means a t-test isn't actually valid here (we should use the non-parametric alternative `wilcox.test()` instead), but for the sake of showing you how one works in R, let's run it anyway. We can compare this to the non-parametric test in a minute.

To run a t-test in R, use the `t.test()` function, and provide it three arguments:

-   A formula of the format `y ~ x` (outcome ~ grouping variable)
-   `data`, the dataframe that contains columns `y` and `x` from the formula
-   `var.equal = TRUE` for a Student's t-test (assuming variances are equal) or `var.equal = FALSE` for Welch's t-test (assuming variances are not equal)

```{r}
t.test(
  weight_lost_g ~ sex, # compare weight lost across sex
  data = dosage, # use dosage data
  var.equal = TRUE # student t-test
  )
```

The p value (4.90e-16) is much smaller than 0.05, suggesting (as the output says), that there is a difference in the mean amount of weight lost by female and male mice. This is not unexpected: we know that male mice weigh more to begin with, so they therefore have more weight to lose than female mice.

### Comparing more than two groups: ANOVA {#sec-anova}

The t-test only compares two groups, so while we could use it to compare male vs female mice, if we want to compare `weight_lost_g` across all three mouse strains at once, we need its multi-group extension: the ANOVA (analysis of variance). Rather than comparing two means directly, ANOVA compares the variance **between** groups to the variance **within** groups, to test whether at least one group mean differs from the others.

Again, let's begin by visualising what we are about to test:

```{r}
ggplot(dosage, aes(x = mouse_strain, y = weight_lost_g)) +
  geom_boxplot()
```

Note that, just like for the t-test, ANOVA assumes our continuous variable is approximately normally distributed (which we can check using a QQ-plot or Shapiro-Wilks test):

```{r}
# make a qq plot
ggplot(dosage, aes(sample = initial_weight_g)) +
  geom_qq() +
  geom_qq_line() +
  # facet because we need to check normality for each group
  facet_wrap(~mouse_strain)

# shapiro-wilks test
dosage %>%
  filter(mouse_strain == "BALBc") %>%
  # shapiro.test() needs a vector, so use pull()
  pull(weight_lost_g) %>%
  shapiro.test()

dosage %>%
  filter(mouse_strain == "Black6") %>%
  pull(weight_lost_g) %>%
  shapiro.test()

dosage %>%
  filter(mouse_strain == "CD1") %>%
  pull(weight_lost_g) %>%
  shapiro.test()
```

This time, we're actually only violating the normality assumption for the CD1 strain (p value 0.04)! We'll compare the result to a the non-parametric Kruskal-Wallace test later, but for now let's proceed with the ANOVA:

We can perform an ANOVA in R using the `aov()` function, with the same `y ~ x` formula notation we used for the t-test:

```{r}
aov(weight_lost_g ~ mouse_strain, data = dosage)
```
Although the way we use the `aov()` function is quite similar to `t.test()`, the output looks very different! We can't see a p-value anywhere. This is because, statistically, ANOVAs are a special case of a linear model (see @sec-lm) and so the output of the `aov()` function inherits some quirks from how linear models are reported in R.

To find the p-value and answer our question, we can pass this to the `summary()` function:

```{r}
aov(weight_lost_g ~ mouse_strain, data = dosage) %>% summary()
```
The p value is extremely small, so we conclude that `weight_lost_g` differs between at least one pair of strains. This matches our observation from the boxplot above, where Black-6 mice visibly lost more weight than BALBc or CD1 mice.

We can also get a tidy version of this table with the `tidy()` function from the `broom` package:

```{r}
aov(weight_lost_g ~ mouse_strain, data = dosage) %>% tidy()
```

This could be useful if, for example, we wanted to extract the p value and use this in further R code (e.g. to label a plot).

::: {.callout-tip title="Which pairs of groups differ?"}
A significant ANOVA (or Kruskal-Wallis) result only tells us that one group differs from another, but it doesn't say which pair(s). We can find this by performing what's known as a 'post-hoc pairwise test' (e.g. Tukey's HSD (honest significant difference) test):

```{r}
aov(weight_lost_g ~ mouse_strain, data = dosage) %>% TukeyHSD()
```
This shows us that there is a statistically significant difference between Black-6 and BALBc mice, as well as betwen CD-1 and Black-6 mice, but **not** between CD-1 and BALBc mice, which matches our observations in the boxplot above.

:::

Unlike for `t.test()`, the `aov()` function doesn't have an argument for equal variances. If your variances aren't equal, you need to instead use the `oneway.test()` function, which does have this argument:

```{r}
oneway.test(weight_lost_g ~ mouse_strain, data = dosage, var.equal = FALSE)
```

### Non-parametric tests {#sec-non-para}

When a parametric assumption (i.e. normality) is badly violated, we can turn to a non-parametric alternative instead. These tests don't assume the outcome is normally distributed and instead test for differences in the ranks of the data.

::: {.callout-warning title="Assumptions of the Wilcoxon and Kruskal-Wallis tests"}
-   Observations are independent of one another
-   The outcome variable is at least ordinal (i.e. it can be meaningfully ranked)
-   If you want to interpret the result as a difference in medians specifically (rather than just 'the distributions differ'), the groups should have similarly shaped distributions
:::

Non-parametric tests are more robust to outliers and skewed distributions than their parametric counterparts, **but** they can be somewhat less powerful to detect a true effect when the data are actually normally distributed. Therefore, you should only use them when you really need to.

#### The Wilcoxon rank-sum test {#sec-wilcox}

The Wilcoxon rank-sum test (also called the Mann-Whitney test when applied on two samples, like we will do here) is the non-parametric equivalent of the t-test we covered earlier. Instead of comparing means, it tests whether one group tends to have overall higher or lower ranked values than the other.

Let's revisit our comparison of `weight_lost_g` between male and female mice. We can use it by simply replacing `t.test()` with `wilcox.test()`

```{r}
wilcox.test(weight_lost_g ~ sex, data = dosage)
```

The p value is again far smaller than 0.05, so both tests agree here: male and female mice differ in weight lost.

#### The Kruskal-Wallis test {#sec-kruskal}

The just like the t-test, the Wilcoxon test only compares two groups. The non-parametric version of the ANOVA we ran above is called the Kruskal-Wallis test, and we can run it using the `kruskal.test()` function:

```{r}
kruskal.test(weight_lost_g ~ mouse_strain, data = dosage)
```

## Correlation between continuous variables {#sec-correlation}

So far, we have considered situations where both, or one of our variables were categorical. If both of our variables are continuous, we can measure the strength and direction of a linear relationship between them using a correlation coefficient.

A correlation coefficient ranges from -1 to 1, where:

-   Values close to **1** indicate a strong *positive* relationship (as one variable increases, so does the other)
-   Values close to **-1** indicate a strong *negative* relationship (as one variable increases, the other decreases)
-   Values close to **0** indicate little to no linear relationship

::: {.callout-warning title="Assumptions of the Pearson correlation"}
-   The relationship between the two variables is linear (check with a scatterplot before you calculate r!)
-   Both variables are continuous
-   No extreme outliers, which can heavily distort the correlation coefficient
-   Ideally, both variables are roughly normally distributed

If any of these are violated (e.g. the relationship is non-linear, or there are outliers), use the non-parametric Spearman correlation instead. Spearman correlation only assumes the relationship is monotonic, since it works on the ranks of the data rather than the raw values.
:::

Let's examine the correlation between `drug_dose_g` and `weight_lost_g`.

First, check the linearity assumption with a scatterplot:

```{r}
ggplot(dosage, aes(x = drug_dose_g, y = weight_lost_g)) +
  geom_point() +
  # add geom_smooth to compare the points to a linear
  # line of best fit
  geom_smooth(method = "lm") +
  labs(
    x = "Drug dose (g)",
    y = "Weight lost (g)",
    title = "Correlation between drug dose and weight lost"
  )
```

A straight line looks like a reasonable summary of this relationship, and there don't seem to be any crazy outliers, so let's go ahead and calculate the correlation coefficient. We can do this in R using `cor.test()`:

```{r}
# cor.test() takes two arguments, the x and y variables
# remember these must be vectors: access from df with $
cor.test(dosage$drug_dose_g, dosage$weight_lost_g)
```

The correlation coefficient (0.87) is close to 1, and the p value is far smaller than 0.05, so we have strong evidence of a **positive linear relationship** between drug dose and weight lost. In other words, mice given a higher dose of mousezempic tended to lose more weight.

::: {.callout-note title="Pearson vs Spearman correlation"}
`cor.test()` calculates a **Pearson correlation** by default, which as discussed above has a number of assumptions.

If your data are not normally distributed, contain outliers, or the relationship is monotonic but not linear (e.g. curved but always increasing), a **Spearman correlation** is a better choice. You can perform one using the `method` argument of `cor.test()`:

```{r}
cor.test(dosage$drug_dose_g, dosage$weight_lost_g, method = "spearman")
```
:::

## Visualising statistical tests with ggpubr {#sec-ggpubr}

So far, we've been running our tests and making our plots in two separate steps. The `ggpubr` package (which extends ggplot2) makes it easy to combine the two, by adding the result of a statistical test directly onto a plot as an annotation. This is a great way to make quick, publication-ready figures without having to manually copy test statistics and p values into a title or label.

### Adding a test result to a boxplot

The `ggboxplot()` function works similarly to `ggplot() + geom_boxplot()`, but returns a plot we can layer statistical annotations onto with `stat_compare_means()`.

Let's revisit our comparison of `weight_lost_g` between male and female mice, this time adding the t-test result directly onto the plot:

```{r}
ggboxplot(
  data = dosage,
  # unlike in the ggplot() function, x and y are
  # supplied directly, not in aes()
  x = "sex", y = "weight_lost_g",
  # in ggpubr, you add jitter using the 'add' argument
  add = "jitter") +
  stat_compare_means(method = "t.test") +
  labs(x = "Sex", y = "Weight lost (g)")
```

The same idea works for our three-strain comparison, using `method = "kruskal.test"` (or `method = "anova"`):

```{r}
ggboxplot(dosage, x = "mouse_strain", y = "weight_lost_g", add = "jitter") +
  stat_compare_means(method = "kruskal.test") +
  labs(x = "Mouse strain", y = "Weight lost (g)")
```

We can get `ggpubr` to add pairwise comparisons too, by supplying a list of the pairs we're interested in to the `comparisons` argument:

```{r}
ggboxplot(dosage, x = "mouse_strain", y = "weight_lost_g", add = "jitter") +
  # get the pairwise comparisons
  stat_compare_means(
    comparisons = list(c("BALBc", "Black6"), c("BALBc", "CD1"), c("Black6", "CD1"))) +
  # get the overall p value and test name
  stat_compare_means(method = "kruskal.test", label.y = 8) +
  labs(x = "Mouse strain", y = "Weight lost (g)")
```

This runs a pairwise Wilcoxon test for each pair of strains we listed, adding a significance bracket for each comparison, alongside the overall Kruskal-Wallis result. Annoyingly, we have to run `stat_compare_means()` twice, because each call only adds one type of label of the plot (either the pairwise comparisons **or** the overall p value and test name), but this is the struggle that comes with using functions written by other people, sometimes the interface doesn't quite make sense!

### Adding a correlation to a scatterplot

Similarly to `ggboxplot()`, `ggscatter()` is another higher-level plotting function from `ggpubr`. It creates a scatterplot that we can annotate with `stat_cor()` to show the correlation coefficient and p value:

```{r}
ggscatter(dosage, x = "drug_dose_g", y = "weight_lost_g", add = "reg.line") +
  stat_cor(method = "pearson") +
  labs(x = "Drug dose (g)", y = "Weight lost (g)")
```

Just like `cor.test()`, we can switch to a Spearman correlation with the `method` argument:

```{r}
ggscatter(dosage, x = "drug_dose_g", y = "weight_lost_g", add = "reg.line") +
  stat_cor(method = "spearman") +
  labs(x = "Drug dose (g)", y = "Weight lost (g)")
```

::: {.callout-note title="ggpubr and ggplot2"}
Since `ggpubr` functions return ordinary ggplot objects, you can keep layers to them, like `theme_minimal()`, `labs()` or even `facet_wrap()`. This makes `ggpubr` a nice shortcut for making plots, while still retaining the customisation abilities you learnt in workshop 4.

## Linear modelling (in the tidyverse) {#sec-lm}

As you may recall from lecture 4, linear models are very useful for testing for significant associations between variables, or significant differences between groups. They have the advantage of being able to correct for the effects of other variables, and thereby remove unwanted sources of variation that could otherwise reduce our ability to discover true relationships.

::: {.callout-warning title="Assumptions of linear regression"}
-   **Linearity**: the relationship between each predictor and the outcome is a straight line
-   **Independence**: the residuals (the differences between observed and predicted values) are independent of one another
-   **Homoscedasticity**: the residuals have roughly constant variance across the range of fitted values
-   **Normality of residuals**: the residuals are approximately normally distributed (this matters most for small samples — with a large enough sample, the model is fairly robust to this)
-   For multiple regression specifically: predictors shouldn't be too strongly correlated with one another (multicollinearity)
:::

### Testing differences between groups (discrete x)

Earlier in this workshop (see @sec-ttest), we used an independent t-test to check whether `weight_lost_g` differs between male and female mice. A **simple linear regression** with a single, two-level categorical predictor is mathematically identical to that t-test.

Let's try running one, using `lm()` to demonstrate this. Note that just like the `aov()` function, we need to pipe this into `summary()` to get a p value:

```{r}
lm(weight_lost_g ~ sex, data = dosage) %>% summary()
```

Compare the `statistic` and `p.value` for `sexmale` to the t-test we ran earlier (t = -8.54, p = 4.9e-16, using `var.equal = TRUE`) — they match exactly. The `intercept` term is the mean for the reference group (`female`, since it comes first alphabetically), and `sexmale` is the estimated *difference* between the male and female group means.

The same is true of ANOVA: `lm(y ~ group)` with a 3+ level categorical predictor gives the same F-statistic and p value as `aov(y ~ group)`.

### Testing differences relative to 0 (discrete x)

But what if we don't want to compare the male vs female mice, and instead are just interested in knowing whether either sex lost a meaningful amount of weight at all? This type of model could be useful, for example, if you were doing an experiment to compare a standard cancer treatment to a new drug: you might want to see how much each of these treatments affect survival relative to the baseline.

Keeping with the previous example of weight lost vs sex, if we use `lm(weight_lost_g ~ 0 + sex)` we get the mean weight lost per group as the `estimate`, and each group mean is tested against 0 rather than against the other group:

```{r}
lm(weight_lost_g ~ 0 + sex, data = dosage) %>% summary()
```

Both p values are very significant (because average weight lost is nowhere near 0 g in either group). However, it is important to note that we cannot conclude from this whether male and female mice differ *from each other*: that comparison requires the `weight_lost_g ~ sex` model we used above.

### Testing associations between variables (continuous x)

Of course, `lm_test()` works just as well for a continuous predictor. Earlier we used `cor.test()` to test the association between `drug_dose_g` and `weight_lost_g` (see the scatter plot with fitted line above), and a simple linear regression tests the same relationship, while additionally estimating a slope and intercept:

```{r}
lm(weight_lost_g ~ drug_dose_g, data = dosage) %>% summary()
```

The p value matches the significance we saw from `cor.test()`, and the (very large) slope tells us that weight lost increases steeply with drug dose. The slope is high because `drug_dose_g` is measured in tiny fractions of a gram, so a one-unit increase in dose is an enormous increase in practice.

### Making linear modelling tidy
Similarly to how the `tidy()` function from the `broom` package can be used to create tidy versions of the statistical tests we've covered throughout this workshop, the `lm_test()` function from the `tidyrstats` package can be used to make linear modelling tidy. This is helpful if you then want to go on to do additional calculations with the results, for example to create a `ggplot2` visualisation.

Another advantage is that because `data` is the first argument of `lm_test()`, we can pipe data into it:

```{r}
dose_model <- dosage %>%
  lm_test(weight_lost_g ~ drug_dose_g)

dose_model
```

We can visualise this tidy fitted model with a scatterplot and a line of best fit:




```{r}

  filter(term == "intercept") %>%
  pull(estimate)

model_slope <- dose_model %>%
  filter(term == "drug_dose_g") %>%
  pull(estimate)

model_pvalue <- dose_model %>%
  filter(term == "drug_dose_g") %>%
  pull(p.value)

ggplot(dosage, aes(x = drug_dose_g, y = weight_lost_g)) +
  geom_point() +
  # draw the fitted line using the intercept/slope estimated by lm_test()
  geom_abline(intercept = model_intercept, slope = model_slope, colour = "blue") +
  # add the p value as a text label in the top-left corner of the plot
  annotate(
    "text",
    x = -Inf, y = Inf, # hack to put in top-left corner

    # format.pval is a base R function to format p values
    # in a nice human readable way

  ) +
  labs(
    x = "Drug dose (g)",
    y = "Weight lost (g)",
    title = "Relationship between drug dose and weight lost"
  )
```

You might be wondering why we would do this rather than simply using `geom_smooth()` or `ggscatter()`, as we have already done in this workshop. It's important to understand that these functions fit their own model as part of the plotting, between the x and y variables on your plot. For the simple model we have just fitted between drug dosage and weight loss, it doesn't matter, because the models made by `geom_smooth()` and `ggscatter()` are identical to the one we've done with `lm()`, but as your models become more complex, the `lm_test()` approach becomes necessary to visualise your actual model on a scatterplot.

### Correcting for covariates

So far we have tested relationships between a independent (x) and a dependent (y) variable.

Often we want to ensure that other possible sources of variation are minimised so that we can better detect true differences in our 'main effect of interest'. Say we want to understand whether drug dose affects weight lost *regardless of mouse strain*. In other words, we want to subtract the mean effect of any strain-specific differences.

We already saw in our ANOVA and Kruskal-Wallis tests earlier that `weight_lost_g` differs noticeably between strains (Black6 mice lose more weight on average). Therefore, mouse strain is a plausible confounder of the drug dose/weight lost relationship.

To test the dose effect while correcting for strain, we can add `mouse_strain` to the model:

```{r}
dosage %>%
  lm_test(weight_lost_g ~ drug_dose_g + mouse_strain)
```

The estimated slope for `drug_dose_g` drops from about 5015 (t ≈ 32.6) in the uncorrected model above, to about 4061 (t ≈ 13.2) once we adjust for strain — some of the raw dose/weight-lost association was indeed attributable to strain differences. Even so, the p value for `drug_dose_g` remains far below 0.05, so drug dose seems to have a genuine effect on weight lost that is only *partly* explained by strain.

### The role of linear modelling in bioinformatics
Everything we've covered today is the basic statistical foundation for the more advanced bioinformatics techniques we'll learn in upcoming workshops. A differential expression analysis, for example, fits exactly the same kind of linear model we've built today, just repeated across thousands of outcomes at once (individual genes, proteins or metabolites), while correcting for confounders like batch effects, and handling data that's rarely as well-behaved as ours (requiring extra filtering, transformation, and care around mean-variance relationships). Doing this at scale is a computationally demanding task, which is why R packages such as limma and edgeR, bundle the expression data, sample/gene metadata and model design together into a single specialised object, then fit all of the models and generate thousands of results in one command. We'll learn about this workflow in upcoming workshops.

Linear modelling is also foundational to machine learning, which focuses on trying to use the coefficients from a fitted model, combined with the predict() function, to make predictions about new data. We'll explore machine learning in more detail in our final workshop.

That is, within any given strain, higher doses are actually associated with longer tails. **The uncorrected relationship was driven entirely by strain differences**, not a true dose effect in the opposite direction. We saw a similar flip in workshop 4, when adding colour to a scatterplot changed our interpretation of the relationship between initial weight and tail length (see @sec-workshop04).
