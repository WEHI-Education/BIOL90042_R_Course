28  Tutorial 11: Unsupervised Machine Learning in R

Workshop 8 focussed on how we develop supervised machine learning models in R using the tidymodels package (create a recipe, specify a model, bundle a workflow, and fit) which we can use when our data has labels: where we know what each grouping should be.

But what happens when we don’t know this?

This is when we use unsupervised machine learning, which aims to discover patterns or structures in the data without prior knowledge of the groupings. We have already come across Multidimensional Scaling (MDS) plots in workshop 7, and you may have encountered Principal Components Analysis (PCA), k-means clustering or hierarchical clustering in your research so far.

In this tutorial, we will reuse the same workflow concepts you learned in Workshop 8 (recipe → model → workflow → fit), but apply them to an unsupervised task: k-means clustering with the tidyclust package.

TipLearning Objectives

This workshop directly builds on Workshop 8. At the end of this session, learners should be able to:

  1. Understand the difference between supervised and unsupervised machine learning and explore their applications in biomedical research.
  2. Construct a complete tidymodels workflow: create a recipe, specify a model, bundle a workflow, to train a k-means clustering algorithm.
  3. Fit a k-means model, inspect centroids, and assign cluster predictions to observations
  4. Evaluate clusters against known biological groupings

The key difference between supervised and unsupervised machine learning in our current tidymodels workflow is shown in the figure below:

For supervised ML, the pipeline we followed included splitting our dataset into a training and testing dataset, our recipe contained both an outcome and predictor variable/s, we set the model (e.g., random forest), engine (R package) and mode (classification or regression), bundled the workflow, fit the model and then evaluated model performance.

For unsupervised ML, the pipeline differs in that we will not be splitting our dataset into train/test sets, our recipe does not need an outcome predictor variable (as we do NOT know the outcome), we set the model (e.g., k-means clustering), engine (R package) and do not need to set a mode, bundle the workflow and fit the model.

We cannot explicitly evaluate model performance in the same way because there are no labels to measure against. Instead there are other, relative, measures we can employ to test how well our model performs. One such measure is the silhouette score, which measures cluster geometry (how compact and well-separated the clusters are) rather than correctness. It is as a way to compare results, like different values of k, not whether the clustering is “correct”. This still requires biological prior knowledge. You can read more about the silhouette scores and plots in the extension section below.

28.2 K-Means Clustering with tidyclust

Using our noisy_dosage dataset, our aim is to apply an unsupervised machine learning model to cluster mouse strains based on physiological and dosage features only.

For this tutorial, we will be training a k-means clustering model.

NoteWhat is a k-means clustering algorithm?

Let’s work through an example used in the lecture.

You’re opening three new coffee shops in a city and want to know where the best place is for students to gather. You have data showing where 100 students like to hang out. How do you decide the best locations?

Because you’re a coding expert, you decide to use a k-means clustering algorithm to solve this by finding three natural “meeting spots” in your data.

  1. Pick three (k = 3) random locations on the map as your starting coffee spot positions. These are your initial centres.
  2. Assign each student to the nearest centre based on their location to the initial centres.
  3. Move the centre to the middle of each group of students. This creates a new centre which is more representative of where students are.
  4. Repeat from step 2 until nothing changes. When the centres are stable, it means that you have found the natural meeting spot you’re after!

K-means clustering algorithms are iterative and repeatedly ask: 1. Who belongs to each group? 2. Where should each group’s centre be? 3. Repeat until stable: this leads us to the best possible solution

Note: Alternatively you could work through this process by asking: how many coffee shops would fit for this cohort of 100 students? This would require the use of tuning the k parameter to see how many coffee shops would best suit this dataset. You can read more on how to do this in our extension sections below.

28.2.1 Prepare the Data

In this tutorial we apply unsupervised learning to the noisy_mousezempic_dosage_data dataset, but this time pretending we do not know the strain labels.

The noisy_mousezempic_dosage_data dataset contains measurements for 344 mice across three strains (CD1, BALBc, and Black6) housed across three cages.

NoteBiological Prior: How Many Clusters Should We Expect?

The best results will be obtained with prior knowledge of the optimal cluster number (k).

For the mousezempic dataset, we have a clear biological prior: there are 3 known strains: CD1, BALBc, and Black6. This gives us a strong reason to expect k = 3 to be the most biologically meaningful solution, so we set k = 3 directly in our model. An optional extension later in this session uses silhouette analysis, a data-driven approach, to confirm or challenge this prior.

We are going to explicitly keep only the numeric physiological features of our dataset and remove any missing values. Strain labels are deliberately excluded as we are aiming to use unsupervised learning: we do not want to inform the algorithm about strain identity.

28.2.3 Define a Preprocessing Recipe

Recall from Workshop 8 that a recipe specifies the variables to include in the model and the preprocessing steps to apply, expressed as a statistical formula: outcome variable ~ predictor variables .

There is one key difference here from the supervised case: in unsupervised learning, we have no outcome variable because we do not know the class labels. Our recipe formula is therefore ~ . (no outcome, all predictors).

As we saw in our figure above, the x- and y-axes are on markedly different scales. As in Workshop 8, we normalise the data to place all variables on a common scale where the mean = 0 and standard deviation = 1.

NoteWhy is normalisation essential for k-means?

K-means clustering assigns observations to clusters based on Euclidean distance, the straight-line distance between points in feature space. If one variable is measured in grams (thousands) and another in millimetres (tens), the gram variable will dominate the distance calculation, regardless of its biological relevance. Normalisation removes this scale bias.

Just like in workshop 8, we first initialise our k-means clustering algorithm by defining our recipe and add any pre-processing steps. Here, we are going to normalise all of our numeric predictors just like in our workshop. Note because we removed all categorical predictor variables, we do not need to apply the step_dummy() function to categorical (nominal) variables.

kmeans_recipe <- recipe(~., data = dosage_clust) %>%
  step_normalize(all_numeric_predictors())

28.2.4 Specify the K-Means Model

Now that we have our recipe, we can specify our model using the k_means() function from tidyclust . We set our engine (set_engine()) to "stats" , which uses base R’s built-in kmeans() function. We do not need to set a mode here because we are doing unsupervised ML (whereas for supervised ML, we need to specify "regression" or "classification").

Setting num_clusters = 3 fixes the number of clusters up front, using our biological prior of three known strains. (An optional extension below shows how to choose k from the data instead, using silhouette tuning.)

Setting nstart = 25 runs the algorithm 25 times with different random centroid initialisations and keeps the best result. This is important because k-means is sensitive to where the centroids start.

WarningWhat is a centroid? And why does it need to be initialised?

A centroid is the point at the center of a cluster: you can think of it as the cluster’s “address”.

K-means has to start somewhere, so it begins by placing the centroids at random positions. It then gradually moves them to better positions, step by step, until they settle. The catch is that where they start affects where they end up: an unlucky random start can lead to a poor final clustering, even with the same data.

To avoid relying on luck, we simply run the algorithm many times from different random starts and keep the best result. That is exactly what nstart = 25 does below: it runs k-means 25 times and keeps the run where the points are tightest around their centroids.

kmeans_spec <- k_means(num_clusters = 3) %>% # our model
  set_engine("stats", nstart = 25) # our engine

TipExtension: Choosing k with a Data-Driven Approach (Silhouette Tuning)

In the main workflow we set num_clusters = 3 directly from our biological prior. But what if we did not know how many groups to expect? The silhouette score offers a data-driven way to choose k: it measures how well each observation fits its assigned cluster relative to neighbouring clusters. This extension shows two routes — a quick one-liner, and the full tidymodels tuning approach.

28.2.5.1 A quick route: fviz_nbclust()

The silhouette score is computed from pairwise Euclidean distances between mice — the same distances k-means uses. Just as in our recipe, those distances must be computed on normalised data, otherwise the variable with the largest units dominates. Rather than scaling by hand, we extract exactly the normalised data the model saw from our fitted recipe using prep() + bake():

# Extract the scaled data from the fitted recipe
scaled_data <- kmeans_recipe %>%
  prep() %>%
  bake(new_data = dosage_clust)

# Try a range of k values and plot the average silhouette for each
fviz_nbclust(scaled_data, kmeans, method = "silhouette")

28.2.5.2 The full route: tuning over values of k with tune_cluster()

The full route uses the same tune_*() machinery you saw for supervised models in Workshop 8. To use it, we would change our model specification to k_means(num_clusters = tune()). Here we evaluate k from 2 to 8 clusters. We cap at 8 as there is no biological reason to expect more than a small number of morphologically distinct mouse groups. Recall that our biological prior suggests k = 3 (three strains).

# A tuning version of our specification and workflow:
# num_clusters is now a placeholder to be tuned, not fixed at 3
kmeans_spec_tune <- k_means(num_clusters = tune()) %>%
  set_engine("stats", nstart = 25)

kmeans_workflow_tune <- workflow() %>%
  add_recipe(kmeans_recipe) %>%
  add_model(kmeans_spec_tune)

kmeans_grid <- tibble(num_clusters = 2:8)

We create 10 bootstrap resamples of the data to obtain more stable silhouette estimates. We then tune the workflow across all values of k, collecting the silhouette_avg metric: a measure of how well each observation fits its assigned cluster relative to neighbouring clusters.

# Insert a seed because this step involves randomness!
set.seed(123)

kmeans_resamples <- bootstraps(dosage_clust, times = 10)

kmeans_tuning <- tune_cluster(
  kmeans_workflow_tune,
  resamples = kmeans_resamples,
  grid = kmeans_grid,
  metrics = cluster_metric_set(silhouette_avg)
)

TipInterpreting the silhouette plot

The silhouette score ranges from -1 (poor, misassigned points) to +1 (optimal, well-separated clusters). In this analysis, the silhouette is actually maximised at k = 2, not at our biological prior of k = 3. This is a common and instructive result: the silhouette criterion rewards well-separated clusters, so when two groups lie close together in feature space it prefers to merge them. Here, k = 2 largely lumps BALBc and CD1 mice into a single cluster while separating Black6 mice. That is a worse biological solution even though it scores better geometrically.

This is why the silhouette score should inform, not dictate, the choice of k. With a strong biological prior of three known strains, we select k = 3. Its silhouette remains positive (~0.2), indicating that the three-cluster solution still captures real structure: just with two strains that partially overlap.

Solutions

TipExtension: Per-Observation Silhouette Plot

The silhouette plots in the tuning extension showed the average silhouette for each value of k. Here, for our fitted k = 3 model, we look at the silhouette width of each individual mouse, which reveals borderline observations. We again extract the normalised data from our fitted recipe, because the silhouette is computed from pairwise distances in the same scaled feature space the model used.

  prep() %>%
  bake(new_data = dosage_clust)

28.3 k-Means vs Hierarchical Clustering

The lecture also introduced hierarchical clustering as a second unsupervised approach. Rather than iterating on centroids, hierarchical clustering builds a dendrogram (‘clustering tree’) by repeatedly merging the two closest samples or clusters, starting with every sample as its own cluster and finishing with a single cluster containing everything.

The number of clusters is not fixed in advance: instead, you cut the dendrogram at a chosen distance/height, and the number of branches crossed determines the number of clusters. This is different from k-means, where num_clusters must be specified before fitting.

If you are interested in building a hierarchical clustering workflow, you can use functions hier_clust() from the tidyclust R package. See this tutorial here.

  3. Hierarchical clustering relies entirely on a distance (or similarity) metric between all pairs of samples.

discover patterns or structures in the data **without prior knowledge 
of the groupings**. We have already come across Multidimensional 
Scaling (MDS) plots [in workshop 7](@sec-workshop07), and you may have 
encountered Principal Components Analysis (PCA), k-means clustering or

The key difference between supervised and unsupervised machine learning
in our current `tidymodels` workflow is shown in the figure below: 

![](images/T11F01_workflow.png)

For **supervised ML**, the pipeline we followed included splitting our dataset
into a training and testing dataset, our recipe contained both an outcome
and predictor variable/s, we set the model (e.g., random forest), engine 
(R package) and mode (classification or regression), bundled the workflow, 
fit the model and then evaluated model performance. 

For **unsupervised ML**, the pipeline differs in that we will not be 
splitting our dataset into train/test sets, our recipe does not need an 
outcome predictor variable (as we do NOT know the outcome), we set the model
(e.g., k-means clustering), engine (R package) and do not need to set a mode, 
bundle the workflow and fit the model. 

We cannot explicitly evaluate model performance in the same way because 
there are no labels to measure against. Instead there are other, relative, 
measures we can employ to test how well our model performs. One such measure 
is the [silhouette score](#sec-silhouette){.quarto-xref}, which measures 
cluster *geometry* (how compact and well-separated the clusters are) rather
than correctness. It is as a way to compare results, like different values of 
*k*, not whether the clustering is "correct". This still requires biological
prior knowledge. You can read more about the silhouette scores and plots in
the [extension section](@sec-silhouette) below.

## K-Means Clustering with tidyclust {#sec-t11-kmeans}

Using our `noisy_dosage` dataset, our aim is to apply an unsupervised 
machine learning model to cluster mouse strains based on physiological
and dosage features only.

For this tutorial, we will be training a k-means clustering model.

::: {.callout-note title="What is a k-means clustering algorithm?"}

Let's work through an example used in the lecture. 

You're opening three new coffee shops in a city and want to know where 
the best place is for students to gather. You have data showing where 
100 students like to hang out. How do you decide the best locations? 

Because you're a coding expert, you decide to use a k-means clustering
algorithm to solve this by finding three natural "meeting spots" in 
your data.

![Please note that this image was generated using ChatGPT and was given explicit instructions to visualise the k-means clustering algorithm process for this coffee shop example.](images/T11F02_kmeans.png)

1. Pick three (k = 3) random locations on the map as your starting coffee 
  spot positions. These are your **initial centres**. 
2. Assign each student to the nearest centre based on their location to
  the initial centres. 
3. Move the centre to the middle of each group of students. This creates
  a new centre which is more representative of where students are. 
4. Repeat from step 2 until nothing changes. When the centres are stable, 
  it means that you have found the natural meeting spot you're after! 

K-means clustering algorithms are iterative and repeatedly ask: 
1. Who belongs to each group? 
2. Where should each group's centre be? 
3. Repeat until stable: this leads us to the best possible solution

*Note*: Alternatively you could work through this process by asking:
how many coffee shops would fit for this cohort of 100 students? This
would require the use of tuning the *k* parameter to see how many
coffee shops would best suit this dataset. You can read more on how 
to do this in our [extension sections](#extension) below.
:::

### Define a Preprocessing Recipe {#sec-kmeans-recipe}

Recall from Workshop 8 that a
**[recipe](wk11_fr.qmd#recipe){.quarto-xref}** specifies the variables
to include in the model and the preprocessing steps to apply, expressed
as a statistical formula: `outcome variable ~ predictor variables` .

There is one key difference here from the supervised case: in
**unsupervised learning**, we have **no outcome variable** because we do 
not know the class labels. Our recipe formula is therefore `~ .` (no
outcome, all predictors).

As we saw in our figure above, the x- and y-axes are on markedly
different scales. As in Workshop 8, we **normalise** the data to place
all variables on a common scale where the mean = 0 and standard
deviation = 1.

::: {.callout-note title="Why is normalisation essential for k-means?"}
K-means clustering assigns observations to clusters based on **Euclidean 
distance**, the straight-line distance between points in feature space.
If one variable is measured in grams (thousands) and another in
millimetres (tens), the gram variable will dominate the distance
calculation, regardless of its biological relevance. Normalisation
removes this scale bias.
:::

Just like in [workshop 8](workshop_8.qmd#define-a-preprocessing-recipe), 
we first initialise our k-means clustering algorithm by defining our 
recipe and add any pre-processing steps. Here, we are going to 
normalise all of our numeric predictors just like in our workshop. *Note*
because we removed all categorical predictor variables, we do not need
to apply the `step_dummy()` function to categorical (nominal) variables.

```{r}
#| label: clustering-recipe
#| 
kmeans_recipe <- recipe(~., data = dosage_clust) %>%
  step_normalize(all_numeric_predictors())

summary(kmeans_recipe)
```

### Specify the K-Means Model {#sec-kmeans-specify}

Now that we have our recipe, we can specify our model using the 
`k_means()` function from `tidyclust` . We set our engine 
(`set_engine()`) to `"stats"` , which uses base R's built-in 
`kmeans()` function. We **do not** need to set a mode here because
we are doing unsupervised ML (whereas for supervised ML, we 
need to specify `"regression"` or `"classification"`).

Setting `num_clusters = 3` fixes the number of clusters up front, using
our **biological prior** of three known strains. (An optional extension
below shows how to choose *k* from the data instead, using silhouette
tuning.)

Setting `nstart = 25` runs the algorithm 25 times with different random
centroid initialisations and keeps the best result. This is important
because k-means is sensitive to where the centroids start.

::: {.callout-warning title="What is a centroid? And why does it need to be initialised?"}

A **centroid** is the point at the center of a cluster: you can think
of it as the cluster's "address".

K-means has to start somewhere, so it begins by placing the centroids at
**random** positions. It then gradually moves them to better positions,
step by step, until they settle. The catch is that where they start
affects where they end up: an unlucky random start can lead to a poor
final clustering, even with the same data.

To avoid relying on luck, we simply run the algorithm many times from
different random starts and keep the best result. That is exactly what
`nstart = 25` does below: it runs k-means 25 times and keeps the run
where the points are tightest around their centroids.
:::

```{r}
#| label: kmeans-spec

kmeans_spec <- k_means(num_clusters = 3) %>% # our model
  set_engine("stats", nstart = 25) # our engine

kmeans_spec
```

:::::::::: {#extension .callout-tip title="Extension: Choosing k with a Data-Driven Approach (Silhouette Tuning)" collapse="true"}

In the main workflow we set `num_clusters = 3` directly from our
biological prior. But what if we did *not* know how many groups to
expect? The **silhouette score** offers a data-driven way to choose *k*:
it measures how well each observation fits its assigned cluster relative
to neighbouring clusters. This extension shows two routes — a quick
one-liner, and the full `tidymodels` tuning approach.

#### A quick route: `fviz_nbclust()`

The silhouette score is computed from **pairwise Euclidean distances**
between mice — the same distances k-means uses. Just as in our recipe,
those distances must be computed on **normalised** data, otherwise the
variable with the largest units dominates. Rather than scaling by hand,
we extract exactly the normalised data the model saw from our fitted
recipe using `prep()` + `bake()`:

```{r}
#| label: extension-fviz-nbclust

# Extract the scaled data from the fitted recipe
scaled_data <- kmeans_recipe %>%
  prep() %>%
  bake(new_data = dosage_clust)

# Try a range of k values and plot the average silhouette for each
fviz_nbclust(scaled_data, kmeans, method = "silhouette")
```

#### The full route: tuning over values of k with `tune_cluster()` {#sec-kmeans-tuning}

The full route uses the same `tune_*()` machinery you saw for supervised
models in Workshop 8. To use it, we would change our model specification
to `k_means(num_clusters = tune())`. Here we evaluate *k* from 2 to 8
clusters. We cap at 8 as there is no biological reason to expect more than 
a small number of morphologically distinct mouse groups. Recall that our 
biological prior suggests *k* = 3 (three strains).

```{r}
#| label: clustering-grid

# A tuning version of our specification and workflow:
# num_clusters is now a placeholder to be tuned, not fixed at 3
kmeans_spec_tune <- k_means(num_clusters = tune()) %>%
  set_engine("stats", nstart = 25)

kmeans_workflow_tune <- workflow() %>%
  add_recipe(kmeans_recipe) %>%
  add_model(kmeans_spec_tune)

kmeans_grid <- tibble(num_clusters = 2:8)
```

We create 10 **bootstrap resamples** of the data to obtain more stable
silhouette estimates. We then tune the workflow across all values of
*k*, collecting the `silhouette_avg` metric: a measure of how well each
observation fits its assigned cluster relative to neighbouring clusters.

```{r}
#| label: tune-clusters

# Insert a seed because this step involves randomness!
set.seed(123)

kmeans_resamples <- bootstraps(dosage_clust, times = 10)

kmeans_tuning <- tune_cluster(
  kmeans_workflow_tune,
  resamples = kmeans_resamples,
  grid = kmeans_grid,
  metrics = cluster_metric_set(silhouette_avg)
)

collect_metrics(kmeans_tuning)
```

We now have an averaged silhouette estimate for each value of *k*, where
values range from -1 (misclassified) to +1 (well-clustered). A score >
0.5 generally indicates reasonable cluster structure.

#### Silhouette Plot Across k {#sec-silhouette}

We can visualise the mean silhouette width for each value of *k* using
`ggplot2` . The red dashed line marks our biological prior of *k* = 3,
allowing us to assess whether the data-driven optimum agrees with our
prior knowledge.

```{r}
#| label: silhouette-plot

kmeans_tuning %>%
  collect_metrics() %>%
  filter(.metric == "silhouette_avg") %>%
  ggplot(aes(x = num_clusters, y = mean)) +
  geom_line(colour = "steelblue", linewidth = 1) +
  geom_point(colour = "steelblue", size = 3) +
  # extra things we can add to our silhouette plot
  geom_errorbar(
    aes(ymin = mean - std_err, ymax = mean + std_err),
    width = 0.2,
    alpha = 0.6
  ) +
  geom_vline(
    xintercept = 3,
    linetype = "dashed",
    colour = "firebrick",
    linewidth = 0.8
  ) +
  scale_x_continuous(breaks = 2:8) +
  labs(
    title = "Average Silhouette Width by Number of Clusters",
    x = "Number of Clusters (k)",
    y = "Mean Silhouette Width"
  )
```

::: {.callout-tip title="Interpreting the silhouette plot"}
The [silhouette score](wk11_fr.qmd#silhouette-score){.quarto-xref}
ranges from **-1** (poor, misassigned points) to **+1** (optimal,
well-separated clusters). In this analysis, the silhouette is actually
**maximised at k = 2**, not at our biological prior of k = 3. This is a
common and instructive result: the silhouette criterion rewards
well-separated clusters, so when two groups lie close together in
feature space it prefers to merge them. Here, k = 2 largely lumps BALBc
and CD1 mice into a single cluster while separating Black6 mice. That
is a worse *biological* solution even though it scores better *geometrically*.

This is why the silhouette score should inform, not dictate, the choice
of `k`. With a strong biological prior of three known strains, we
select **k = 3**. Its silhouette remains positive (~0.2),
indicating that the three-cluster solution still captures real
structure: just with two strains that partially overlap. 
:::

## k-Means vs Hierarchical Clustering {#sec-hierarchical}

The lecture also introduced **hierarchical clustering** as a second
unsupervised approach. Rather than iterating on centroids, hierarchical
clustering builds a
**[dendrogram](wk11_fr.qmd#dendrogram){.quarto-xref}** ('clustering
tree') by repeatedly merging the two closest samples or clusters,
starting with every sample as its own cluster and finishing with a
single cluster containing everything.

The number of clusters is not fixed in advance: instead, you *cut* the
dendrogram at a chosen distance/height, and the number of branches
crossed determines the number of clusters. This is different from
k-means, where `num_clusters` must be specified before fitting.

If you are interested in building a hierarchical clustering workflow, 
you can use functions `hier_clust()` from the `tidyclust` R package. 
See this tutorial 
[here](https://tidyclust.tidymodels.org/articles/hier_clust.html).

`tidymodels` in R: creating a recipe, specifying a model, creating a
workflow and fitting a model as we learned in 
[workshop 8](@sec-workshop08) but instead of training a **supervised**
random forest classiifer using known strain labels, here you trained
an **unsupervised** k-means clustering algorithm to recover those same
groupings without any labels, discovering that the physiological
features alone carry enough signal to distinguish the three strains.

Here's what we covered in this session: 

-   Differences between supervised and unsupervised machine learning
    in the `tidymodels` workflow
-   What a k-means clustering algorithm is and how we can train one
-   Creating a recipe for an unsupervised machine learning algorithm where
    we do not have an outcome variable: `~ predictor variables`
-   Specifying a k-means clustering algorithm with a set value for `k` 
    (and optionally: when we do *not* set a value of `k`)
-   Fitting the model on our dataset
-   Comparing our clustering results with our known mouse strain results
